# Changelog

All notable changes to this project are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses
[semantic versioning](https://semver.org/spec/v2.0.0.html).

## [1.0.0] - 2026-09-20

Complete rebuild of the original two-file prototype (`source_code.py` and
`pygui.py`) into an installable, tested package.

### Fixed

- **Saved plots were always blank.** The GUI called `plt.show()` and then
  `plt.savefig()` on the same figure. Interactively, `show()` blocks until the
  window is closed and leaves no current figure behind, so `savefig()` created
  a fresh empty one and wrote that. The thumbnails displayed in the window
  were blank canvases. Reproduced and measured: 2.4 KB blank file versus
  19.5 KB with the data. Plots are now drawn into embedded canvases and never
  routed through pyplot's global state.

- **The GUI froze during simulation.** `plt.show()` on the main thread blocked
  the Qt event loop for as long as the plot window stayed open. Simulations
  now run on a `QThread` and report back by signal.

- **`source_code.py` crashed when run.** Its `sim.sample(101)` call sat
  outside the `with Simulation()` block, so it raised
  `AttributeError: 'NoneType' object has no attribute 'get_pin_index'` on a
  detached circuit. The equivalent call in the simphony backend is now inside
  the context manager, with a comment recording why.

- **Repeated runs stacked curves.** Nothing cleared the axes between runs, so
  each simulation layered new lines over the previous ones. The canvas now
  clears before every redraw, and a test asserts the line count stays constant
  across runs.

- **The sixth component slot was ignored.** Validation only inspected slots one
  to five. A user could put anything in slot six and it had no effect.

### Added

- **A real netlist layer.** `Circuit` validates a component chain
  structurally and recognises its topology. Supported: straight links and
  single-stage Mach-Zehnder interferometers.

- **Specific error messages.** Every rejection names the problem and suggests a
  fix, replacing the single message "There is something wrong with the
  connection! Please, check the circuit components' order." The GUI validates
  continuously while editing rather than only on Run.

- **An analytic backend.** Closed-form transfer functions in NumPy, now the
  default. No optional dependencies, millisecond runtimes, and physics that
  can be checked against textbook relations.

- **A command-line interface.** `machdesigner sweep`, `monte-carlo`,
  `compare`, `backends`, and `gui`. Makes the tool scriptable and lets CI
  exercise the physics without a display.

- **A test suite**: 109 tests. The physics tests validate against derived
  relations rather than recorded output — the cosine-squared law to 1e-12,
  `FSR ∝ 1/dL`, energy conservation, group index against a numerical
  derivative, and cross-agreement between the two backends.

- **Result metrics and export.** Insertion loss, extinction ratio, and free
  spectral range measured from the trace, with CSV and JSON export. The
  analytic backend also reports the closed-form FSR prediction alongside the
  measured value.

- **An aliasing warning.** `UnderSampledSweepWarning` fires when the sweep is
  too coarse to resolve the fringes, instead of silently plotting an aliased
  trace. The original's fixed 500-point sweep aliased badly for large arm
  imbalances.

- **Reproducible Monte Carlo.** Seeded by default, with percentile bands and
  FSR statistics across the ensemble. The original regenerated parameters
  through simphony with no seed control, so runs could not be reproduced.

- **Packaging and CI.** `pyproject.toml` with optional extras, a GitHub
  Actions matrix across Python 3.10-3.13, ruff, and mypy.

- **Documentation.** `docs/physics.md` gives every equation, every default
  parameter with its justification, and an explicit limitations section.

### Changed

- **Split simulation from presentation.** The physics is a library; the GUI and
  CLI are thin front ends. Previously the simulation was inlined in a Qt
  button handler and could not be used without a display.

- **Real Qt layouts.** The window was generated by Qt Designer with absolute
  `setGeometry` coordinates, so it could not resize and broke under different
  fonts or platform scaling. Rebuilt with layouts.

- **Per-slot waveguide lengths.** Arm lengths came from two fixed spin boxes
  that were unrelated to which slots held waveguides. Each waveguide slot now
  owns its length field.

- **Floating-point lengths.** Lengths were integer micrometres (1-9999). They
  are now floating point with a far wider range.

- **simphony is optional and pinned.** `simphony>=0.6,<0.7`. Version 0.7
  replaced the `simphony.simulation` API (`Laser`, `Detector`, `Simulation`)
  that the original was written against; asking for the backend without it
  installed now produces an explanation rather than an `ImportError`
  traceback.

- **Corrected terminology.** The original README described the waveguide
  length inputs as "wavelengths". They are lengths. Typos in user-visible
  strings are fixed ("Theoritically", "Wavequide", "Circut").

### Removed

- **Dead code.** A `print(self.comp_1.currentIndex)` guarded by a condition
  that was always false at setup time, and which printed a bound method rather
  than calling it.

- **`Illustration.png`.** Referenced by the GUI but never present in the
  repository, so the label silently rendered empty.

### Breaking changes

- The canonical MZI is now a six-component chain with two explicit waveguide
  slots: `GC in -> Y-split -> waveguide -> waveguide -> Y-combine -> GC out`.
  The original recognised a five-slot form and took both arm lengths from
  separate spin boxes. `Circuit.from_legacy_indices()` still accepts the
  original integer dropdown encoding, and `ComponentType` values deliberately
  match the original dropdown indices.
